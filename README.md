# Zher Monitoring — Telegram-бот для земельного мониторинга

Zher Monitoring — это Telegram-бот для фиксации и сопровождения проблем, связанных с земельными участками в Казахстане. Пользователь работает с сервисом прямо в Telegram: отправляет геолокацию, фотографию и описание проблемы, проверяет статус заявки и получает инструкции по земельным процедурам.

Бот не заменяет официальные государственные сервисы. Его задача — помочь человеку быстро собрать первичные доказательства, понять следующий шаг и не потеряться между картой, eOtinish, кадастровыми сервисами и внутренним Django API.

## Что умеет бот

- При первом сообщении предлагает `Қазақша` или `Русский`, сохраняет выбор и показывает интерфейс на выбранном языке.
- Принимает сигнал о проблеме с участком: геолокация, фото, описание.
- Обрабатывает настоящую геометку Telegram без предварительного выбора меню: проверяет координаты, определяет регион по полигонам OpenStreetMap, показывает точку на карте и сохраняет результат в обращении.
- Разбирает описание как кейс нарушения: определяет тип ситуации, предполагаемый ответственный орган, срочность, нужные доказательства и пакет готовых текстов обращения.
- Передает сигнал в API через `POST /api/reports`.
- Показывает номер принятого сигнала только после успешного ответа API.
- Сохраняет владельца сигнала и показывает личный кабинет `Мои обращения`: список, статус, фото, место, паспорт нарушения, отдельные тексты обращения и следующий шаг.
- Проверяет статус заявки по номеру через `GET /api/applications/:trackingNumber`.
- Показывает справочник земельных процедур через `GET /api/procedures` или локальные mock-данные.
- Работает в тестовом режиме `mock`, когда backend еще не подключен.
- Регистрирует команды `/start`, `/reports`, `/language` и `/cancel` в Telegram.

## Пользовательские сценарии

### Первый запуск и язык

При первом `/start` или другом сообщении в личном чате бот показывает выбор `Қазақша / Русский`. До выбора языка основные сценарии не запускаются. После выбора открывается главное меню на выбранном языке.

Выбор сохраняется по Telegram ID в `data/user-preferences.json` и действует после перезапуска бота в обоих режимах данных. Повторный `/start` сразу открывает меню. Сменить язык можно кнопкой `Язык / Тіл` или командой `/language`; после подтверждения нового языка текущий незавершённый диалог сбрасывается, сохранённые обращения остаются.

Переведены меню, подсказки отправки сигнала, проверка заявления, кабинет и локальный справочник процедур. Описания пользователей не переводятся. Произвольный текст из backend остаётся в исходном виде, если backend не предоставил перевод; для процедур поддерживается `translations.kk` с текстовыми полями, для пояснения заявления `translations.kk.explanation`.

### 1. Сообщить о проблеме

Пользователь нажимает `Сообщить о проблеме`. Бот по шагам просит:

1. Отправить геолокацию участка или координаты текстом: `51.12955, 71.41540` (широта, долгота). Некорректные координаты можно исправить без сброса сценария.
2. Отправить фотографию.
3. Описать, что произошло.

Можно сразу отправить геолокацию через вложение Telegram (в том числе выбранное место, `venue`). В свободном личном чате также принимается пара координат текстом. Если язык ещё не выбран, бот запомнит геометку и обработает её после выбора RU/KK. Новая геометка начинает новый черновик: старое фото к ней не переносится. Отмена: `/cancel`. Сообщения из групп не меняют личные черновики.

#### Что реально проверяется по геолокации

`src/location.js` проверяет диапазоны широты и долготы и вычисляет попадание точки в реальные административные полигоны через Turf. В комплекте 20 регионов Казахстана, включая Абай, Жетісу, Ұлытау и города республиканского значения. Бот показывает регион, координаты, переданную Telegram точность GPS, дату данных и ссылку на карту. Точка на границе помечается отдельно; если совпадения нет, бот просит проверить координаты, не выдумывая регион. Трансляция геопозиции фиксируется только как первая точка, движение не отслеживается.

Границы: OpenStreetMap contributors, [ODbL 1.0](https://www.openstreetmap.org/copyright). Снимок, источник и контрольная сумма находятся в `assets/geo/kz-regions.geojson`. Геопроверка работает локально без OpenAI и без передачи координат стороннему геокодеру. При открытии ссылки на карту координаты передаются OpenStreetMap. В режиме `api` они также передаются настроенному backend вместе с обращением.

Результат `locationAnalysis` сохраняется с обращением и показывается в кабинете после перезапуска. Для API-режима backend должен сохранять и возвращать это поле; старые обращения без него продолжают открываться. Это справочное определение региона, не официальный кадастр, не адресный поиск и не спутниковый анализ. Собственника, кадастровый номер и факт нарушения бот по одной точке не определяет. Наличие GPS-точности не гарантирует нахождение внутри региона с учётом погрешности.

Обновление границ выполняется отдельно, не при каждом сообщении или запуске:

```powershell
npm.cmd run update:boundaries
npm.cmd test
```

Можно задать `OVERPASS_ENDPOINT` для другого публичного Overpass-сервера. Скрипт заменяет файл только после успешной загрузки полного набора. Подробности и условия распространения: `assets/geo/README.md`.

После этого бот создает сигнал и прикладывает `casePassport`: тип ситуации, предполагаемый ответственный орган, срочность, чеклист доказательств, черновик обращения, повторное обращение, жалобу на бездействие, публичный текст и следующий шаг. В режиме `api` данные уходят в Django API. В режиме `mock` сигнал сохраняется локально как демонстрационная запись.

### 2. Проверить заявку

Пользователь выбирает `Проверить заявление`, вводит номер заявки, например `KZ-2026-042`, и получает статус, пояснение и дату обновления.

### 3. Посмотреть земельные процедуры

Пользователь открывает раздел `Земельные процедуры` и выбирает тему:

- сведения о земельном участке;
- изменение целевого назначения;
- обращение в госорган;
- демо-сигнал в режиме `mock`.

Каждая процедура содержит шаги, срок, примечание, источник и ссылку на официальный сервис.

### 4. Мои обращения

Кнопка `Мои обращения` или команда `/reports` открывает кабинет в личном чате с ботом:

- обращения отсортированы от новых к старым, по 5 на странице;
- карточка содержит номер, статус, дату создания, описание, координаты, паспорт нарушения и следующий шаг;
- отдельные кнопки открывают готовые тексты: черновик, повторное обращение, жалобу и публичный текст;
- можно открыть сохранённое фото, место на карте и обновить статус;
- карточка и фото доступны только владельцу, в том числе при нажатии старых кнопок;
- кнопка `К списку` возвращает на страницу обращения, `Главное меню` возвращает к другим действиям.

В `mock` отправленные сигналы сохраняются в `data/reports.json` с `telegramUserId` и остаются доступны после перезапуска. Старые записи без владельца не удаляются, но в кабинет не попадают: определить их владельца задним числом невозможно. Незавершённые черновики по-прежнему хранятся только в памяти.

Статус демо-сигнала означает сохранение внутри бота, а не регистрацию в госоргане. Кабинет показывает текущий статус; журнал всех изменений статуса пока не ведётся.

## Архитектура

Проект написан на Node.js и использует Telegraf.

Основные файлы:

- `src/index.js` — точка входа.
- `src/bot.js` — логика Telegram-бота, меню, шаги диалога.
- `src/location.js` — проверка координат и определение региона по реальным географическим границам.
- `assets/geo/` — снимок границ с источником и лицензией; `scripts/update-boundaries.mjs` обновляет его.
- `src/case-analysis.js` — разбор описания проблемы в паспорт нарушения: категория, орган, срочность, доказательства и черновик.
- `src/report-cabinet.js` — список обращений, карточки, фото и навигация кабинета.
- `src/i18n.js` — русские и казахские тексты основных сценариев, даты и сообщения об ошибках.
- `src/user-preferences.js` — постоянное хранение языка пользователя.
- `src/reports.js` — проверка владельца, фильтрация и сортировка обращений.
- `src/api.js` — слой доступа к API или mock-режиму.
- `src/mock-api.js` — локальная имитация backend API.
- `src/procedures.js` — справочник земельных процедур.
- `src/config.js` — чтение переменных окружения.
- `src/startup.js` — настройка профиля Telegram-бота и запуск.
- `test/` — тесты конфигурации, сценариев, mock API и запуска.

## Режимы данных

### `DATA_MODE=mock`

Режим по умолчанию. Подходит для разработки и демонстрации без backend.

В этом режиме:

- сигналы сохраняются локально в `data/reports.json`;
- кабинет показывает сохранённые сигналы текущего пользователя;
- язык пользователя хранится отдельно от обращений в `data/user-preferences.json`;
- доступна тестовая заявка `KZ-2026-042`;
- процедуры берутся из `src/procedures.js`;
- бот явно сообщает, что данные демонстрационные и не отправляются в госорганы.

### `DATA_MODE=api`

Режим для работы с реальным Django API.

В этом режиме:

- бот отправляет сигналы в `API_BASE_URL`;
- статусы заявок и процедуры загружаются из backend;
- ошибки API показываются пользователю понятным сообщением.

Django backend не входит в этот репозиторий. Для кабинета он должен сохранять `telegramUserId` при создании сигнала и реализовать новый `GET /api/reports?telegramUserId=...` по контракту ниже. Без этого метода кабинет в режиме `api` покажет ошибку сервиса. В режиме `mock` backend не нужен.

## Требования

- Node.js 22+
- Telegram Bot Token от BotFather
- Django API, если используется `DATA_MODE=api`

## Быстрый запуск

```powershell
npm install
Copy-Item .env.example .env
```

Заполните `.env`:

```env
BOT_TOKEN=your_bot_token_here
DATA_MODE=mock
API_BASE_URL=http://127.0.0.1:8000/api
```

Запуск:

```powershell
npm.cmd start
```

Команда запускает Telegram polling и следит за изменениями в `src/`, `.env` и `package.json`. После сохранения бот автоматически перезапускается с новым кодом. `npm.cmd run dev` включает тот же режим. Сохранение обращений в `data/`, правки документации и тестов не вызывают перезапуск. Для остановки нажмите `Ctrl+C`.

Режим слежения использует Node.js на Windows или macOS. Для запуска без слежения, в том числе на Linux-сервере: `npm.cmd run start:once` (на Linux: `npm run start:once`). При установке новых зависимостей сначала выполните `npm.cmd install`.

При частых перезапусках установите `TELEGRAM_SETUP_PROFILE=false` в `.env`, чтобы не обновлять имя и описание при каждом сохранении и не получать лимит Telegram. Чтобы обновить профиль и меню команд, верните `true` на один запуск.

Режим работает, пока запущен процесс слежения и компьютер включён. После перезагрузки компьютера его нужно запустить снова. Запускайте только одну копию бота с одним токеном. Незавершённый диалог при перезапуске сбрасывается; сохранённые обращения и выбранный язык остаются.

## Railway: только Telegram-бот

Сервис `pesok-gos` в проекте `hospitable-light` использует ветку `master` репозитория `almaz-svg/pesok-gos`. В этой ветке бот находится в корне; сайт и Django здесь не разворачиваются.

- Root Directory: `/`; сборка Railpack с Node.js 22 и командой проверки `npm test`.
- Start Command: `node src/index.js` (без `--watch`). Одна реплика, без cron, публичного домена и HTTP healthcheck; спящий режим отключён.
- Постоянный Volume: `/app/data`. Он хранит обращения, выбранные языки и историю ИИ-чата между деплоями.
- Переменные сервиса: `BOT_TOKEN`, `DATA_MODE=mock`, `NODE_ENV=production`, `RAILPACK_NODE_VERSION=22`, `TELEGRAM_SETUP_PROFILE=false`, `TELEGRAM_STARTUP_TIMEOUT_MS=30000`.
- Перезапуск при ошибке: `ON_FAILURE`, не более 10 повторов. После исчерпания попыток нужно проверить логи и причину сбоя.

Токены задаются только в Variables Railway, не в Git. Не запускайте локальную polling-копию одновременно с облачной. Локальная папка `data/` автоматически в Railway не переносится: перед миграцией сохраните её отдельно. В `mock` данные не отправляются в Django или государственные органы.

## Обсуждение с ИИ

Кнопка `Обсудить проблему` и команда `/ask` открывают отдельный диалог в личном чате. `/newchat` очищает историю этого пользователя. В OpenAI передаются текст разговора и сведения о последних обращениях только текущего владельца; фотографии не отправляются. История хранится локально в `data/ai-history.json`, не более 12 сообщений на пользователя.

Для включения нужен `OPENAI_API_KEY`; без него остальные функции бота работают, а обсуждение с ИИ сообщает, что оно не подключено. `OPENAI_MODEL` по умолчанию равен `gpt-4.1-mini`. Живой вызов OpenAI не проверяется модульными тестами.

До публичного включения ИИ-чата нужны пользовательские квоты и контроль расходов: сейчас код ограничивает только одновременные запросы одного пользователя, но не их суммарное количество. ИИ не отправляет официальные обращения, не меняет статусы и не проверяет актуальность законов в интернете.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `DATA_MODE` | `mock` или `api` |
| `API_BASE_URL` | Базовый адрес Django API |
| `TELEGRAM_API_ROOT` | Адрес Telegram API, обычно менять не нужно |
| `TELEGRAM_STARTUP_TIMEOUT_MS` | Таймаут настройки Telegram-профиля |
| `TELEGRAM_SETUP_PROFILE` | `false`, если не нужно обновлять имя, описание и команды бота |
| `OPENAI_API_KEY` | Необязательный секрет для включения обсуждения с ИИ |
| `OPENAI_MODEL` | Модель ИИ, по умолчанию `gpt-4.1-mini` |
| `RAILPACK_NODE_VERSION` | Версия Node.js для сборки в Railway: `22` |

Не публикуйте `.env` и токен бота в GitHub или чатах.

Файлы `data/reports.json`, `data/user-preferences.json` и `data/ai-history.json` исключены из Git. При переносе бота сохраняйте эти файлы, чтобы не потерять обращения, выбранные языки и историю обсуждений.

## Контракт Django API

Все ответы API должны быть JSON.

Формат ошибки:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Заявление не найдено"
  }
}
```

### `POST /api/reports`

Создает сигнал о проблеме.

Запрос:

```json
{
  "telegramUserId": "123456789",
  "lat": 43.238949,
  "lon": 76.889709,
  "description": "На участке ведутся земляные работы",
  "telegramFileId": "telegram_file_id",
  "casePassport": {
    "type": "illegal_construction",
    "typeLabel": "Стройка или земляные работы",
    "responsibleAuthority": "Архитектурно-строительный контроль, местный акимат или профильное управление города",
    "urgency": "high",
    "evidenceChecklist": [
      "Фото строительных работ и техники",
      "Фото паспорта объекта или его отсутствия на площадке",
      "Геолокация или точные координаты участка"
    ],
      "officialDraft": "Прошу провести проверку по сообщению о возможном нарушении...",
      "followUpDraft": "Прошу повторно рассмотреть ранее поданное обращение...",
      "inactivityComplaintDraft": "Жалоба на бездействие по обращению о земельной проблеме...",
      "publicText": "Нужна публичная проверка...",
      "nextAction": "Проверьте черновик и отправьте официальное обращение через eOtinish или профильный орган.",
    "followUpDays": 3
  }
}
```

Ответ:

```json
{
  "id": "REP-2026-001",
  "status": "signal_received",
  "createdAt": "2026-09-25T00:00:00.000Z"
}
```

`telegramUserId` обязателен: бот берёт его из `ctx.from.id`, а не из текста сообщения, и передаёт строкой с положительным целым числом.

### `GET /api/reports?telegramUserId=123456789`

Возвращает все сигналы конкретного пользователя. Поддерживаются массив записей или объект `{ "reports": [...] }`. В текущей версии страницы формирует бот; backend не должен молча обрезать ответ до первой страницы.

```json
    {

      "telegramUserId": "123456789",
      "status": "under_review",

      "updatedAt": "2026-09-25T06:00:00.000Z",
      "description": "На участке ведутся земляные работы",
      "lat": 43.238949,
      "lon": 76.889709,
      "telegramFileId": "telegram_file_id",
      "caseStatus": "draft_ready",
      "casePassport": {
        "type": "illegal_construction",
        "typeLabel": "Стройка или земляные работы",
        "responsibleAuthority": "Архитектурно-строительный контроль, местный акимат или профильное управление города",
        "urgency": "high",
        "evidenceChecklist": ["Фото строительных работ и техники"],
        "officialDraft": "Прошу провести проверку по сообщению о возможном нарушении...",
        "followUpDraft": "Прошу повторно рассмотреть ранее поданное обращение...",
        "inactivityComplaintDraft": "Жалоба на бездействие по обращению о земельной проблеме...",
        "publicText": "Нужна публичная проверка...",

    }
  ]
}
```

`id` должен быть уникальным и содержать от 1 до 40 латинских букв, цифр, дефисов или подчёркиваний. `telegramUserId` возвращается для каждой записи; записи без владельца или с другим владельцем бот не показывает. `updatedAt`, `explanation`, `nextStep`, `caseStatus` и `casePassport` необязательны для совместимости со старыми записями. Даты показываются по времени Казахстана. Без фото или корректных координат соответствующие кнопки не появляются.

Статусы сигналов: `signal_received`, `under_review`, `inspection_scheduled`, `approved`, `rejected`. Для неизвестного статуса бот предлагает уточнить его позже. При `demoOnly: true` карточка всегда указывает, что сигнал сохранён только в боте.

Каждое открытие карточки, фото или обновление повторно загружает список владельца. Backend должен сам фильтровать записи по владельцу и разрешать доступ к этому методу только авторизованному сервису бота. Один параметр `telegramUserId` не является авторизацией; дополнительная фильтрация в боте не защищает открытый HTTP API. Механизм авторизации backend в этом репозитории пока не реализован.

## Что важно улучшить дальше

Сейчас реализованы личный кабинет и первый слой паспорта нарушения. Дальше развиваем сопровождение проблемы до результата в согласованном порядке.

Приоритетные улучшения:

1. Личный кабинет обращений: реализован список, текущие статусы, карточка, фото и место.
2. Умная категоризация проблемы: базовый разбор и пакет текстов реализованы; следующий шаг — уточняющие вопросы и подтверждение категории пользователем.
3. Черновик официального обращения для eOtinish: реализованы отдельные тексты для первичного обращения, повторного обращения, жалобы на бездействие и публичного сообщения; следующий шаг — адаптация под конкретный орган и сроки.
4. Напоминания по срокам: когда проверить статус и вернуться к обращению.
5. Админ-карта и антидубли: находить похожие сигналы рядом и анализировать проблемные зоны.

Главная продуктовая цель: бот должен не просто принять жалобу, а помочь человеку пройти путь от фиксации проблемы до понятного результата.
