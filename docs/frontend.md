# Веб-панель инспектора

React 19, Vite 7, JavaScript и Leaflet. Интерфейс включает первый экран с процедурным рельефом, карту, ленту и таблицу обращений, сводные показатели, распределение по статусам и карточки инспектора.

## Запуск

Требуется Node.js 22.12+ (проверено на Node.js 24).

```powershell
npm ci
npm run dev
```

Открыть `http://localhost:5173`. Для проверки production-сборки:

```powershell
npm run build
npm run preview
```

`npm test` запускает тесты доменной логики и HTTP-клиента.

## Страницы и маршрутизация

React Router DOM подключён через `BrowserRouter` в `src/main.jsx`. `src/App.jsx` содержит только маршруты:

- `/` — `OverviewPage`: первый экран и блок «Как это работает».
- `/map` — `MapPage`: карта, фильтры, лента обращений и карточка инспектора.
- `/reports` — `ReportsPage`: таблица обращений и карточка инспектора.
- `/reports?view=analytics` — сохранённая аналитика внутри страницы обращений.
- Остальные адреса показывают страницу 404 со ссылкой на главную.

`SiteLayout` объединяет Header, `Outlet` и Footer. `NavLink` отмечает текущую страницу в Header; внутренние переходы используют `Link`. При смене страницы обновляются заголовок вкладки, фокус основного содержимого и положение прокрутки.

Общие части панели находятся в `components/inspector`, блоки главной — в `components/overview`. Загрузка данных и опрос вынесены в `hooks/useInspectorData.js`; при уходе со страницы запросы отменяются, таймеры и подписки удаляются. На обзоре опрос данных инспектора не запускается. У каждой рабочей страницы собственные фильтры; при переходе между картой и обращениями они сбрасываются, а сохранённые данные остаются в API или demo-хранилище.

Для прямого открытия `/map` и `/reports` статический production-сервер должен отдавать `index.html` для frontend-маршрутов (SPA fallback). Пути `/api` и статических файлов должны обрабатываться отдельно. Vite dev и preview поддерживают такой переход локально.

## Демо

Режим по умолчанию — `demo`. Все участки, обращения, границы и иллюстрации вымышлены, интерфейс явно отмечает DEMO. Подложка — OpenStreetMap с атрибуцией; это не официальный кадастр. Для её загрузки нужен интернет, при сбое точки и полигоны остаются видны с сообщением об ошибке.

Шесть тестовых участков и семь обращений хранятся в `src/data/demo.json`. Изменения сохраняются в localStorage текущего браузера. Кнопка «Добавить демо-сигнал» создаёт учебную запись; она не вызывает настоящий Telegram-бот. Новые записи в другом окне с тем же origin подхватываются опросом. В разделе «О демонстрационном пространстве» можно восстановить исходные демо-данные; сделанные в демо изменения при этом сбрасываются.

Проверка основного сценария:

1. Открыть карту, выбрать жёлтое обращение.
2. Перевести его из «Новое обращение» в «На проверке» и сохранить.
3. Подтвердить нарушение: статус «Нарушение выявлено».
4. Выбрать «Устраняется», назначить контрольный срок и сохранить.
5. Закрыть обращение с обязательным комментарием о результате.
6. Проверить историю, цвет маркера, статус связанного участка и показатели.

Кадастровый поиск и поиск по номеру обращения работают по частичному совпадению. Статус и просроченный срок объединяются с поиском. Вкладка аналитики использует выбранные фильтры; верхние показатели — общие. Экспорт GeoJSON сохраняет отфильтрованные объекты включённых слоёв. Переключатель слоёв не скрывает записи в таблице.

## Подключение Django

Скопировать `.env.example` в `.env` и задать:

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=/api
```

Перезапустить Vite. В development `/api` проксируется на `http://localhost:8000`; при другом адресе изменить `server.proxy` в `vite.config.js`. В production настроить reverse proxy `/api` на Django либо указать полный URL API до сборки. При разных origin сервер должен разрешать точный origin frontend, credentialed CORS и CSRF trusted origins. Предпочтителен общий origin.

Клиент использует сессионную авторизацию, `credentials: include` и CSRF-токен в памяти. API-режим показывает форму входа, демо не подставляется при сетевых ошибках. Секреты и Telegram-токен во frontend не нужны. Все `VITE_*` переменные публичны.

Карта и данные запрашиваются раз в 5 секунд; незавершённые фоновые запросы не запускаются повторно. При возврате на вкладку выполняется обновление. Успешное сохранение инвалидирует данные панели. Ошибки отдельных ресурсов не заменяют корректные данные другого ресурса. Если сервер возвращает `map_limit_exceeded`, карта остаётся доступной для приближения и переходит на запросы с `bbox` видимой области. При медленной или недоступной сети фактическая задержка зависит от API.

Для PATCH передаётся `version`; HTTP 409 требует перечитать карточку и заново внести изменения. При потере ответа на PATCH клиент проверяет актуальную запись и останавливает повторную отправку до явного принятия данных. Фотографии загружаются через URL прокси, возвращённый API, с повтором при ошибке.

## Приоритет контракта

Интеграция следует существующим `contracts/api.ts` и `docs/frontend-api.md`: `NEW`, `INSPECTION`, `VIOLATION`, `IN_PROGRESS`, `RESOLVED`; ответ карты содержит две коллекции `plots` и `reports`.

Прикреплённое исходное ТЗ описывает другую версию API с camelCase и `violationType`. В контракте v0.1 `category` уже принадлежит обращению и не редактируется PATCH-запросом. Поэтому карточка показывает тип нарушения и меняет только разрешённые поля: статус, срок, участок и комментарий. Для редактирования типа сначала нужно согласовать расширение backend-контракта. Цвета ТЗ сохранены: жёлтый — проверка, красный — нарушение/устранение, зелёный — норма/закрыто.

## Границы реализации

Репозиторий содержит frontend, Django API, миграции PostgreSQL и общий контракт. Backend запускается отдельно по инструкции в README; frontend по умолчанию использует demo. Реальный Telegram-диалог и публичный хостинг пока не настроены. Каталог `dist` после сборки готов для размещения на статическом хостинге. Реальные кадастровые сведения и государственные интеграции здесь не публикуются.

Рельеф первого экрана — декоративная графика, а не топографические данные Туркестана. Анимация останавливается вне экрана, на скрытой вкладке и при `prefers-reduced-motion`. Карта и карточки доступны с клавиатуры; мобильная карточка занимает всю ширину экрана.
